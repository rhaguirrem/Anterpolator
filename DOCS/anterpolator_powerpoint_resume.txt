Topic: Estimation of spatial values based on Ant Colony Optimization (ACO)
Author: Roberto Aguirre Maturana, Geologist, Universidad de Chile

PURPOSE OF THE PRESENTATION
The presentation documents the development and testing of “Anterpolator”, a numeric spatial interpolator that estimates values in a 3D grid using an Ant Colony Optimization-inspired process. The slides compare how different movement rules, value-assignment rules, background-value handling, distance/visit decay parameters, domain constraints, and weighting methods affect the spatial continuity, conservativeness, extension, and coverage of the resulting interpolation.

CORE METHOD
1. Input data are samples with known X/Y/Z coordinates and values.
2. The sample volume is divided into a regular 3D grid with user-defined cell size.
3. Each grid cell can have up to 26 neighboring cells.
4. Cells containing samples receive the average sample value of the samples inside the cell.
5. Cells without samples initially have no assigned value unless a background-value option is activated.
6. A user-defined number of ants is generated.
7. Each ant starts randomly in a sampled cell.
8. At each step, the ant predicts the value of its current cell from neighboring-cell values, usually as a weighted average.
9. The predicted value is assigned to the current cell unless it is a sample cell.
10. If the current cell already has a value, the new prediction may replace it or be averaged with the current value using a user-defined cell weight.
11. If the current cell has no value, the prediction may replace it or be averaged with a user-defined background value.
12. The ant then moves to a neighboring cell. Priority rules favor unvisited cells, cells without samples, or cells whose value is close to the current cell according to a tolerance/class-size threshold. If no priority cell is available, movement is random.

MAIN PARAMETERS DISCUSSED
- Cell size: controls the grid resolution.
- Number of ants: controls the number of simultaneous paths exploring/interpolating the grid.
- Iterations: controls how long ants walk through the grid.
- Class size and tolerance: define whether two cell values are considered similar enough for priority movement.
- Cell weight: controls how much existing cell value is retained when averaging with a new prediction.
- Background value: usually 0 in the tests; used to make interpolation more conservative away from samples.
- Background value for None cells / Value for None cells: controls whether empty/unvisited cells are treated as background during prediction or assignment.
- Decay rate: controls how rapidly influence changes with distance or value difference.
- Visit decay lambda: alternative decay based on number of visits instead of distance to samples.
- Sample distance range: limits or prioritizes ant movement around sampled cells.
- Domain average distance / Background distance: controls domain-limited estimation and background behavior.
- Weight method: different ways to weight neighbor cells, including greater_sample, greater_value, nearest_sample, and weights based on difference to the closest sample.
- Fill unvisited cells with neighbors average: optional post-processing to estimate cells never visited by ants.

Slide 35 - Domained estimation, fine 5x5x5 grid

Result: Presents a domained estimation and gives the current neighbor-weighting formula:

This weights neighbors based on the difference between the closest-sample value of the last cell and the candidate neighbor-cell value.

KEY RESULTS AND INTERPRETATION

1. Excluding sampled cells from first-priority movement improved continuity.
The early baseline reached very high coverage, but produced an isolated drillhole section. After changing the priority rule so first-priority neighbors do not include sampled cells, the interpolation became more continuous along isogrades.

2. Cell weight controls conservativeness and memory of previous estimates.
Higher cell weight keeps more of the previous cell value and dampens new predictions. Lower cell weight gives more importance to the ant prediction. A cell weight of 0 behaves like ignoring the existing cell value during interpolation.

3. Background value for None cells makes the interpolation more conservative.
When blank cells are treated as background on first visit, the interpolation is damped toward 0 away from samples. Reducing cell weight can counteract this conservativeness.

4. Class size and tolerance define value-continuity constraints.
A neighbor is considered similar if the absolute difference in values is below class_size * tolerance. Smaller class sizes make the movement rule more restrictive and can help preserve sharper value classes or isograde continuity.

5. Visit decay lambda was not fully satisfactory.
Visit-based decay is intended to make values converge to background according to how many times a cell has been visited, but the tests suggest it did not preserve enough continuity near close samples and could still overextend estimates away from samples.

6. Distance/sample-based decay appears more geologically meaningful than pure visit decay.
Decay rate based on distance to samples better represents the idea that interpolation should fade toward background away from sample support.

7. Sample distance range is a strong control on anomaly extension.
When sample distance range is the only priority rule, ants remain close to samples and visited-cell coverage drops substantially. This makes it useful for limiting anomaly extension, but too restrictive if used alone.

8. Weighting by nearest sample, closest-sample value, or greater sample value supports domain-aware estimation.
The later experiments move toward a more geologically constrained approach where each visited cell stores its closest sample and neighbor weights depend on sample proximity, sample value, or value compatibility.

9. Domain and fault constraints are important.
In the fault-domain example, movement priority considers direction continuity and class/domain consistency. This helps avoid propagation across structural boundaries and makes the algorithm more suitable for geological modeling.

10. Iterations matter more than just increasing ants.
Comparisons show that high ant count with low iterations may cover less of the grid than fewer ants with more iterations. The number of ant movements through time is critical for coverage.

11. Fine-grid domained estimation is computationally large.
In the 5x5x5 grid example, the model has over 3.7 million cells and more than 1 million sampled cells. Coverage is only 34.93% after 500 iterations, suggesting the need for optimization, more iterations, post-fill strategies, or more efficient traversal.

12. Comparison with kriging is included but not quantitatively evaluated in the text.
The presentation shows visual comparisons between Anterpolator and kriging. The text does not provide validation metrics such as cross-validation error, bias, RMSE, slope of regression, or conditional bias, so the comparison is mainly qualitative/visual.

POSSIBLE CODE/IMPLEMENTATION NOTES FOR GPT IN VS CODE

- Represent the grid as a 3D array or sparse dictionary indexed by integer cell coordinates.
- Store for each cell: value, has_sample, sample_value/average, visited_count, closest_sample, distance_to_closest_sample, domain/class mark, and optional pheromone.
- Ant state should include current cell, previous cell, last direction vector, current/last closest sample, and possibly alive/dead status.
- Neighbor search should use the 26 adjacent offsets in 3D.
- Priority rules should be modular:
  a) unvisited cells,
  b) non-sample cells,
  c) cells inside sample distance range,
  d) cells with similar value class,
  e) cells with same domain/class mark,
  f) direction-continuity cells,
  g) pheromone or decay constraints.
- Prediction should be a weighted average of eligible neighbor values.
- Assignment should be configurable:
  a) replace current value with prediction,
  b) average prediction with current value,
  c) average prediction with background for None cells,
  d) dynamic predicted weight based on distance to nearest sample or other decay rule.
- Post-processing can optionally fill unvisited cells using neighbor averages.
- Validation should be added: compare Anterpolator estimates with sample values by leave-one-out or train/test split, then compare with kriging using RMSE, MAE, bias, correlation, and visual residual maps.

ONE-PARAGRAPH SUMMARY
Anterpolator is a prototype 3D spatial interpolator that uses ant-like agents to propagate sample values through a grid. Ants start at sampled cells, estimate current-cell values from neighboring cells, assign predictions according to configurable weighting/background rules, and move through priority-selected neighbor cells. The presentation explores how parameters such as cell weight, class-size tolerance, background handling, sample-distance range, visit decay, distance decay, weighting method, pheromone limits, and domain/fault constraints affect interpolation behavior. The strongest conclusions are that excluding sample cells from first-priority movement improves continuity, background treatment makes results conservative, sample-distance controls are useful for limiting anomaly extension, visit-decay alone is insufficient, and domain/fault constraints are necessary for geological realism. The deck ends with qualitative comparisons between Anterpolator and kriging but does not yet include quantitative validation metrics.
